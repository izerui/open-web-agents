# coze-v3 阶段 5：构建页 Implementation Plan

> **For agentic workers:** 按任务顺序执行；纯逻辑先写失败的 vitest 测试再实现；界面用浏览器对照 `prototype/build.html` 与 `shots/build-*.png` 验证。

**Goal:** `/agents/[id]` 换成「构建页」：一页、一份自动保存的草稿、五个阶段（编排 / 评测 / 发布 / 接入 / 运行）。智能体设计器（原 `/agents/design`）是编排阶段的主角，承接 design-workspace 的全部能力并新增按节应用（A4）与「让设计器修复」（A7）；档案卡九节就地编辑并自动保存（A3）；试聊（A5）与存为用例（A6）；评测花费预估（A9）；上线清单（A8）；版本快照、定向分享（A15）、申请上架（A13）；接入内联签 Key、在线试调（A16）；运行小统计（A17）。

**Architecture:** 新目录 `src/features/build/`。`BuildPage`（AppShell fullBleed + 左侧「我的智能体」列表 + 页头 + 阶段内容）。状态拆成三个 hook：`useAgentDraft`（读取智能体、表单草稿、800ms 防抖自动保存、暂停原因、离开提醒）、`useDesigner`（设计会话：记录、对话、运行、差异、按节应用、基线跟随）、`useTrial`（试聊会话）。所有判断（表单↔配置、保存闸门、九节摘要与是否已填、设计差异按节归类与合并、上线清单、阶段徽标、用例预填、修复提示词、上架申请状态）是纯函数，放 `*.ts` 并单测。可复用的旧子模块（knowledge-*、eval-form、release-panel 的 DiffView、share/mcp-check/model-select、snippets、webhook-*、RunsPanel）直接接入；Builder、DesignWorkspace、AccessCenterView 删除。

**Tech Stack:** Next.js 16 App Router、React、Tailwind v4、shadcn new-york、vitest、biome、drizzle/mysql2。

## 地址

| 地址 | 渲染 |
| --- | --- |
| `/agents/<id>` | 构建页·编排（`?stage=eval\|publish\|access\|runs` 切阶段；`?designer=<会话>` 打开指定设计记录；不带时自动取本智能体最近一次设计记录） |
| `/agents/<id>?tab=<旧分区>` | 重定向：`eval`→`?stage=eval`，`release`→`?stage=publish`，其余去掉 tab（编排） |
| `/agents?id=x&tab=eval` | `legacyRedirect` 直接给 `/agents/x?stage=eval` |
| `/agents/new?designer=<会话>&desc=` | 构建页新建态（设计器从零创建；desc 预填输入框不自动发送） |
| `/agents/new`（无 designer） | 工作室新建弹层（阶段 4，不变） |
| `/agents/design?session=` | 解析后重定向（不变）；不带 session 时渲染构建页新建态 |

## 后端（与前端并行）

- B1 设计器预览返回 `base`（目标当前内容对应的设计草稿），前端据此按节拆分与组合
- B2 会话来源 `trial`：`POST /api/sessions {agentId, trial:true}`（网页 + 写权限，固定草稿）；编排器把 trial 当网页交互；`/chat` 列表不含；运行筛选可选 trial
- B3 `POST /api/agents/[id]/try`、`GET /api/agents/[id]/try?runId=`：登录态在线试调，与 invoke 共用编排与契约校验，来源 invoke、计入本人
- B4 `GET /api/usage?agentId=`：按智能体过滤
- B5 `GET /api/agents/[id]/evals/estimate`：同模型近 20 次已结算运行平均实扣 × 用例数，无样本为 null
- B6 设计会话 `PATCH {bindTarget}`：新建态手填自动保存建出智能体后，让无目标的设计会话认领它

每个接口先写路由测试（模拟容器）或域测试，再实现。
