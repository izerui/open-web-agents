# Open Web Agents · 通用 AI 智能体平台愿景文档

> 本平台是**通用的智能体平台**，适配任何行业：企业、政务、医疗、教育等都可以在上面配置专用智能体，
> 给人用（网页工作台）、给系统用（标准 API）。本文以**高校**作为主要示例场景来说明，
> 其中的“教务系统”“老师/学生”等可以换成任何行业的业务系统与角色。
> 实施优先级以 `docs/reports/2026-10-14-platform-roadmap.md` 的“后续优先级”为准。

## 一、项目背景

高校信息化建设中有两个长期痛点始终没有很好地解决：

**第一，校园各系统想要具备 AI 能力，每次都要单独开发。** 教务系统想加 AI 批改、图书馆想加智能推荐、OA 想加公文辅助……每做一个都要从零对接模型 API、处理提示词工程、解析 AI 输出、管理密钥和费用。做一个再做一个，各自为政，重复投入巨大。

**第二，师生日常工作中有大量可以用 AI 提效的环节，但缺少一个统一的、低门槛的、安全可控的平台。** 工具碎片化、使用门槛高、数据安全无法保障、费用分散不可控。

本项目的出发点就是：**建一个统一的 AI 智能体平台，在上面配置好各种专用智能体，人可以直接网页使用，系统可以通过标准接口接入 —— 无需为每个场景重复开发 AI 能力，一次接入即可持续受益。**

## 二、产品定位

**通用的 AI 智能体平台** —— 类似字节扣子、阿里百炼所做的事情，适配任何行业；可私有部署，由机构统一管控算力、安全和费用。下文以高校为例。

### 两个核心能力，缺一不可

**1. 给人用 —— 网页工作台**

师生通过网页直接与智能体对话交互，看到 AI 的思考过程和产出文件。

**2. 给系统用 —— 标准化接口调用**

学校现有的教务系统、OA、图书馆、LMS 等无需为每个场景重复开发 AI 能力，通过平台提供的标准接口完成接入和结果处理即可获得 AI 能力。在输入输出约定保持一致的前提下，智能体可在平台内持续优化，调用方无感知。

```
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
│ 教务系统  │  │ OA系统   │  │ 图书馆    │  │ LMS      │
└────┬─────┘  └────┬─────┘  └────┬─────┘  └────┬─────┘
     │             │             │             │
     └─────────────┴──────┬──────┴─────────────┘
                          │  标准 API 调用
                          ▼
              ┌─────────────────────┐
              │    AI 智能体平台     │
              │  （各种专用智能体）    │
              └──────────┬──────────┘
                         │
     ┌───────────────────┼───────────────────┐
     ▼                   ▼                   ▼
 结构化数据          文件产物            回调通知
{"分数":85,        报告.pdf           webhook →
 "批注":[...]}     图表.png           通知调用方
```

**这是本项目最初立项的重点考量：** 以前每个系统要整合 AI 能力都是单独做一套 —— 做完一个再做一个，重复劳动。现在在平台上统一配置好智能体，各系统通过标准接口接入即可。无需为每个场景重复开发 AI 能力，智能体在平台内持续优化，只要输入输出约定不变，调用方无感知。**一次接入，持续受益。**

### 同一个智能体，两种使用方式

同一个智能体，配置一次，既能给人用也能给系统调：

| 入口 | 使用者 | 拿到什么 |
|------|-------|---------|
| 网页工作台 | 老师/学生/行政人员 | 流式对话、思考过程、文件产物、交互审批 |
| 系统 API 调用 | 教务系统、OA、LMS 等 | 结构化数据（JSON）、文件产物清单、回调通知 |

**API 调用的关键设计：**
- 一个接口触发，一个接口取结果，自动生成 API 文档和调用示例
- 智能体定义了输出格式后，返回的是经过校验的结构化数据，不是自由文本
- 支持幂等调用 —— 网络故障重试不会重复执行和扣费
- 支持回调通知 —— 智能体执行完后主动通知调用方，不用轮询
- 支持带文件调用 —— 可以把待处理的文件传给智能体

### 每个人既是使用者也是创造者

平台不只是管理员配置好智能体给别人用。每一个角色都可以自主创建：

- **老师**创建教学智能体给学生用，创建工具型智能体给自己用、给其他老师用，也可以创建接口型智能体供教务系统调用
- **学生**创建学习和科研智能体给自己用，使用老师分享的智能体完成学习任务
- **行政人员**创建办公智能体处理日常事务
- **学校管理层**通过平台统一提供 AI 算力，管控安全和费用，也可以创建材料分析、报告汇总等个人工作智能体

所有角色之间通过智能体的创建、分享、克隆、接口对接形成一张**协作关系网** —— 人与人之间通过分享和协作互联，人与系统之间通过接口调用互通。平台就是这张网的中枢，AI 是串联一切的桥梁。

## 三、核心场景

### 场景一：教学闭环 —— 老师构建、学生使用、学情反馈

这是平台最核心的教学场景。

**完整流程：**

```
老师构建智能体
    ↓
上传课件、讲义、参考资料 → 作为智能体的知识库
    ↓
设定学习目标和交付要求 → "学完后需要提交XX"
    ↓
配置交互方式 → 引导式提问、知识点检测、任务拆解
    ↓
试运行满意后 → 分享给班级/年级/全校
    ↓
学生获取后在自己的空间中使用
    ↓
AI 基于老师的讲义和要求，引导学生一步步完成学习任务
    ↓
学生产出交付物（报告/代码/设计/分析结果）
    ↓
提交给老师 → 老师可以用另一个"批改智能体"辅助评审
    ↓
学情数据汇总 → 反馈到教学改进 → 老师据此优化智能体 → 循环
```

**示例：**

> 《数据结构》课程讲完"二叉树"这一章后：
>
> 1. 老师上传课件和讲义，用 AI 创建一个"二叉树学习助手"
> 2. 设定要求："理解遍历算法，提交前/中/后序遍历代码实现，并解释每种遍历的应用场景"
> 3. 分享给班上 60 个学生
> 4. 每个学生在自己的空间中与这个智能体交互 —— 不懂的地方 AI 基于老师的讲义解释，不是泛泛的网上内容
> 5. AI 引导学生按步骤完成：理解概念 → 画出遍历过程 → 写代码 → 测试 → 总结
> 6. 学生完成后提交代码和解释
> 7. 老师用"代码批改助手"快速审阅 60 份提交，输出结构化的评分和批注

**核心价值**：老师把教学意图"编码"进智能体，等于同时给 60 个学生各配了一个了解老师教学思路的 AI 助教。学生得到的不是通用的 AI 回答，而是贴合课程进度和老师要求的针对性辅导。

### 场景二：AI 辅助生成教学内容

| 教学内容 | 做法 | 说明 |
|---------|------|------|
| **教学动画视频** | Manim 数学动画引擎 | 老师输入"演示傅里叶变换的直观含义"，AI 自动生成 Manim 代码并渲染成带动画标注的教学视频。数学、物理、工程类课程的抽象概念可视化，老师无需学习 Manim 编程 |
| **建模图/架构图** | Mermaid / PlantUML | 软件工程、数据库等课程，AI 自动生成 UML 类图、ER 图、流程图、架构图 |
| **课程设计方案** | 基于教学大纲 | 输入课程目标和学时安排，生成完整的课程设计方案（教学目标、内容安排、考核方式） |
| **试卷与题库** | 基于知识点 | 按知识点覆盖度和难度分布自动出题，支持选择、填空、编程、论述等多种题型 |
| **实验指导书** | 基于实验目的 | 生成规范的实验步骤、注意事项和报告模板 |
| **微课脚本** | 基于知识点 | 生成 5-10 分钟的微课讲稿和 PPT 框架 |

### 场景三：论文全流程辅助

| 环节 | 说明 |
|------|-----|
| **文献综述** | 输入研究方向，整理文献脉络、提取关键观点、生成综述框架 |
| **论文结构评审** | 上传论文，从结构完整性、逻辑连贯性、论证充分性等维度给出评审意见 |
| **格式规范检查** | 自动检查引用格式、图表编号、参考文献格式是否符合学校或期刊要求 |
| **查重预检** | 正式查重前做初步检测，标出高风险段落 |
| **翻译润色** | 学术语境下的中英文翻译和专业术语润色 |
| **摘要生成** | 基于全文自动生成中英文摘要 |
| **答辩准备** | 根据论文内容预测答辩问题，辅助准备回答 |

导师可以创建"毕设论文辅导助手"，把写作规范、常见问题和指导建议放进知识库，分享给所带学生。学生写论文过程中随时可以咨询，得到的回答基于导师的标准和要求。

### 场景四：作业批改与学情追踪

不只是单次批改，而是**贯穿学期的持续追踪**：

```
AI 辅助出题 → 学生作答 → AI 按标准批改（分数 + 批注 + 知识点标记）
    → 全班学情汇总（薄弱知识点 / 需关注学生）→ 反馈教学调整 → 循环
```

批改结果是标准化数据（分数、扣分项、知识点掌握度），可以直接导入教务系统或生成统计报表，而不只是一段评语文字。

### 场景五：个人工具箱 —— 每个人的 AI 瑞士军刀

每个人都可以根据自己的需要创建智能体，就像给自己配一把定制的工具：

**老师的工具箱：**

| 工具 | 用途 |
|------|-----|
| 科研申报助手 | 基于申报模板辅助撰写项目申报书 |
| 会议纪要助手 | 上传会议录音，自动生成结构化纪要 |
| 排课建议助手 | 输入约束条件，生成排课方案 |
| 教学评价分析 | 分析学生评教数据，给出改进建议 |
| 个人知识管理 | 整理研究笔记和文献，随时检索回顾 |

**学生的工具箱：**

| 工具 | 用途 |
|------|-----|
| 课程项目助手 | 辅助调研、整理资料、生成初稿 |
| 毕业设计助手 | 选题调研 → 技术方案 → 论文撰写，全流程辅助 |
| 竞赛备战助手 | 数学建模、程序设计等竞赛的分析和可视化 |
| 实验数据处理 | 上传数据，自动做统计分析、拟合、生成图表 |
| 学习计划制定 | 根据课程表和目标生成学习计划 |

**行政人员的工具箱：**

| 工具 | 用途 |
|------|-----|
| 通知撰写助手 | 各类通知、公告、会议纪要 |
| 数据报表助手 | 汇总和分析各类教学行政数据 |
| 后勤报修分派 | 智能分类报修请求，自动派单 |

做出好用的工具后可以发布到市场，全校共享。一位老师做的"科研申报助手"，全校老师都能受益 —— **形成"人人为人人服务"的校内 AI 工具共建共享生态**。

### 场景六：校园系统接口调用 —— 通过标准接口接入，无需重复开发 AI 能力

这是平台最初立项的核心场景。以前每个系统要整合 AI 能力都是单独开发一套，现在统一在平台上配置好智能体，各系统通过标准接口直接调用。

**调用方式极其简单：**

```
第三方系统 → 调用接口，传入数据 → 拿到结构化结果

例：教务系统调用"作业批改智能体"
请求：{ "input": "批改这份作业", "files": [作业文件] }
返回：{ "分数": 85, "扣分项": [...], "批注": [...], "知识点掌握": {...} }
```

调用方不需要知道背后用了什么模型、提示词怎么写、输出怎么解析 —— 这些全部由平台上的智能体配置好了。

**具体场景：**

| 调用方系统 | 调用的智能体 | 传入什么 | 拿回什么 |
|-----------|-----------|---------|---------|
| 教务系统 | 作业批改智能体 | 学生提交的作业文件 | 分数、扣分明细、知识点掌握情况（结构化数据，直接入库） |
| 教务系统 | 试卷生成智能体 | 知识点列表 + 题型要求 | 标准格式的试卷数据（直接导入考试系统） |
| 教务系统 | 学情分析智能体 | 一段时间的成绩数据 | 薄弱知识点排名、需关注学生名单、教学建议 |
| 图书馆系统 | 文献推荐智能体 | 读者的研究方向描述 | 推荐文献列表及推荐理由 |
| OA 系统 | 公文辅助智能体 | 公文类型 + 关键信息 | 符合格式要求的公文初稿 |
| 招生系统 | 招生咨询智能体 | 考生的问题 | 基于招生政策的标准回答 |
| 科研管理系统 | 申报辅助智能体 | 课题信息 + 申报要求 | 申报书各章节的初稿框架 |
| 后勤系统 | 报修分类智能体 | 报修描述文本 | 分类结果 + 优先级 + 建议派单部门 |
| 就业系统 | 简历优化智能体 | 学生简历 | 优化后的简历 + 改进建议 |

**核心价值：以前做一个 AI 集成就要开发一套，现在在平台上配一个智能体，各系统完成接口接入和结果处理即可。无需重复开发 AI 能力，智能体在平台内持续优化而调用方无感知。一次接入，持续受益。**

## 四、智能体市场 —— 全校的"AI 工具超市"

市场是平台的核心入口，所有人打开就能看到可用的 AI 工具。

### 预装智能体分类

**通用教学类：**
试卷生成 / 作业批改 / 教案设计 / 课件生成 / 学情分析 / 课堂答疑 / 教学评价

**理工科专属：**
Manim 教学动画 / 编程导师 / 数据分析 / 实验报告 / 建模图生成 / 数学建模 / 算法可视化

**文科社科类：**
学术翻译 / 文献综述 / 论文评审 / 写作润色 / 案例分析

**行政管理类：**
招生咨询 / 教务问答 / 通知撰写 / 科研申报 / 会议纪要

**学生工具类：**
学习计划 / 复习助手 / 简历优化 / 面试模拟 / 竞赛辅助

### 市场机制

- 任何人都可以发布自己创建的智能体到市场
- 其他人可以直接使用，或克隆后根据自己的需要定制
- 按学科、用途、热度分类浏览
- 使用量和评价公开，便于选择

### 发布与社交（申请审核与可见范围近期做；好友与社交互动后期）

- **发布流程** —— 智能体发布到市场需经过完整的审核或确认流程，确保质量和安全
- **可见范围** —— 发布时可选择可见范围：全平台公开、指定用户/用户组可见（好友可见随好友关系后期再做）
- **好友关系** —— 用户之间可建立好友关系，好友可以看到对方限定可见的智能体
- **社交互动** —— 关注、收藏、评价、使用量排行，形成校内 AI 工具社区氛围

## 五、平台核心能力

| 能力 | 说明 | 带来的价值 |
|------|-----|----------|
| **AI 辅助创建** | 用自然语言描述需求，AI 自动生成智能体配置 | 不懂技术也能 10 分钟做出一个 AI 工具 |
| **知识库** | 上传课件、讲义、论文等资料，AI 基于这些内容回答 | 回答来自老师的材料，而不是泛泛的网络内容 |

| **分享与克隆** | 创建者可以把智能体分享出去，使用者可以克隆后定制 | 教学意图在师生之间精准传递 |
| **多入口使用** | 同一个智能体支持网页对话、系统接口调用 | 一次创建，多场景使用 |
| **安全可控** | 校内私有部署、执行隔离、审计日志、额度管控 | 数据不出校，费用透明可控 |
| **版本管理** | 草稿 → 试运行 → 评测 → 发布，可回滚可追溯 | 智能体质量有保障，迭代有依据 |
| **多模态 AI** | 文本对话、图片理解、图片生成、视频生成、语音能力 | 覆盖教学科研中的各种内容形式 |

## 六、竞品对比

| 维度 | 通用聊天工具 | 扣子/百炼/Dify | 本平台 |
|------|-----------|--------------|-------|
| 面向谁 | 所有人 | 企业和开发者 | **任何行业的机构及其成员（示例：高校师生）** |
| 使用门槛 | 需要会写提示词 | 需要一定技术背景 | **所有人可直接使用和创建** |
| 知识库 | 无或弱 | 有 | **深度绑定课程体系和学术资料** |
| 教学场景 | 无 | 无 | **教学闭环：创建→使用→交付→学情** |
| 结构化输出 | 不支持 | 部分支持 | **可直接对接教务系统** |
| 内容生成 | 文字为主 | 多模态 | **Manim 教学动画/建模图/视频** |
| 数据安全 | 数据在第三方 | 取决于部署方式 | **校内私有部署，数据不出校** |
| 费用管控 | 个人各自付费 | 企业统一付费 | **平台统一积分管控，费用透明** |
| 共享机制 | 无 | 有 Bot 商店 | **校内教学工具共建共享** |

核心差异在于：通用平台没有教学场景设计，本平台从教学科研的根本需求出发，设计了"创建 → 分享 → 使用 → 交付 → 反馈"的完整教学闭环，这是产品骨架层面的差异，不是功能标签的区别。

## 七、平台价值

### 对老师

- **大幅减少重复工作** —— 出题/批改/答疑/备课的效率提升数倍
- **教学意图精准传递** —— 把教学思路和要求融入智能体，每个学生都能获得贴合课程要求的辅导
- **教学资源可积累** —— 好的工具发布到市场后持续发挥价值，不会每学期从零开始
- **零技术门槛** —— AI 辅助创建，不需要学编程或研究 AI

### 对学生

- **全天候个性化辅导** —— 任何时候都有基于老师讲义的 AI 可用，不受答疑时间限制
- **有目标的深度学习** —— AI 按老师设定的目标引导，有明确的交付要求，不是漫无目的地聊天
- **科研和项目全流程提效** —— 文献、翻译、数据、论文、建模，每个环节都有对应工具
- **自主创造** —— 也可以自己创建智能体，锻炼 AI 应用能力

### 对学校

- **智慧校园实质性落地** —— 师生每天在使用的工具，而非概念层面的规划
- **数据安全合规** —— 私有部署，使用全程可审计，满足数据安全要求
- **AI 支出统一管控** —— 一个平台管理所有 AI 费用，积分账单透明可追溯
- **知识资产沉淀** —— 全校共建的 AI 工具库是学校独有的数字资产
- **教学创新示范** —— 在 AI 融入教学方面形成领先优势和标杆效应

## 八、发展愿景

### 近期目标：校内 AI 工具平台

预装教学科研智能体，全校师生可以直接使用和自主创建，形成校内共享市场。平台统一管理 AI 算力和积分费用。

### 中期目标：教学全流程 AI 化

- **空间** —— 把一组智能体、资料和成员放在一起（高校里就是课程空间：答疑 + 资料库 + 作业互动）
- **多模态能力全面接入** —— 手写作业识别、课堂录音转写、教学视频生成、语音合成
- **多端发布** —— 同一个智能体一键发布到企业微信、钉钉、校园 App、微信小程序
- **定时任务** —— 每周自动生成学情周报，每月统计科研进展
- **插件生态** —— 对接知网/万方、LaTeX、SPSS 等学术工具

### 远期目标：教育 AI 生态

- **校际联盟** —— 多所高校共享优质智能体，好的教学工具不局限于一所学校
- **出版社合作** —— 教材出版社为教材配套智能体，平台成为分发渠道
- **产学研闭环** —— 学生在平台上做 AI 应用实训，优秀作品孵化为产品
- **数字孪生教师** —— 基于老师的知识库和教学风格，生成"AI 分身"，全天候辅助教学
- **教育 AI 行业标准** —— 参与制定高校 AI 应用规范和安全标准
- **移动端覆盖** —— 微信小程序和原生 App，随时随地使用 AI 助手

## 九、总结

本平台的定位是一个**让人和系统都能便捷获得 AI 能力的统一平台**。

它解决的核心问题是：以前每个系统想要 AI 能力都要单独开发一套，每个人想用 AI 都要自己找工具。现在在一个平台上统一配置好智能体 —— **人通过网页直接用，系统通过标准接口接入。无需为每个场景重复开发 AI 能力，智能体在平台内持续优化而调用方无感知。一次接入，持续受益。**

在此基础上，它还是每个人手中的 AI 瑞士军刀 —— 每个人都可以创建自己需要的工具，也可以分享给别人，师生之间、系统之间通过智能体构建起一张 AI 协作网络。

平台的核心逻辑：

```
统一配置各种专用智能体
    ↓
┌───────────────┬───────────────────┐
│ 给人用         │ 给系统用            │
│ 网页对话交互    │ 标准接口调用          │
│ 师生直接使用    │ 标准接口接入            │
└───────┬───────┴─────────┬─────────┘
        │                 │
        ▼                 ▼
   分享·克隆·协作      结构化结果·回调通知
   人与人的 AI 网络    系统与系统的 AI 网络
        │                 │
        └────────┬────────┘
                 ▼
    学校统一管控 · 安全可控 · 费用透明 · 资产沉淀
```

项目核心框架已搭建完成，具备演示条件。建议立项后与 2-3 个学院合作试点，快速验证场景价值，逐步推广至全校。
