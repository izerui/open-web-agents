# 平台统一设计与实施清单

本清单替代早期评审报告中的过时进度说明。按完成一项、验收一项、再推进下一项的顺序实施。
不重建 SDK、会话、队列或数据库连接池。既有安全、审批与 GC 正确性修复保留。

计量口径(2026-10-21 确认):按 claude-agent-sdk 报告的输入、输出、缓存读、缓存写 token 正式计费,
读不出或缺失的用量记为计量缺失、保持暂记,不按 0 结清(规则见 `docs/billing.md`)。
供应商 Key 已对智能体的 Bash、hook、stdio MCP 子进程屏蔽(`CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`),
不能被读出来绕过计费。运行级受限凭证与可信网关计量暂不做:对账报表与上游账单持续对不上时再议。
共享 HOME 的租户隔离仍须在开放给互不信任的用户前单独验收。

## 平台定位

最终产品是面向 B 端与 C 端的智能体平台:智能体市场可直接使用,也可通过 AI 创建和维护,
同时提供 Web 对话与第三方 API 调用,所有模型能力统一由平台供给并按积分/套餐结算。
平台提供两类能力,共用账号、权限、用量和账务:

1. 智能体平台:AI/手动创建与维护、网页对话、第三方系统调用。
2. 模型能力平台:LLM、图片生成、视频生成、语音生成、语音理解。

业务智能体通过 Claude Agent SDK 执行;平台模型能力可以作为其受控工具接入。
主推理模型必须兼容现有 SDK 的调用协议,不能声称任意生图或文本 API 都能直接替换 SDK。
将来对外单独提供模型能力 API 时,复用能力调用与计费模块,不另造第二套账务。

## 用户工作流程

    市场选择智能体 → 直接使用 / 新建或定制
    创建智能体 → AI/手动编辑草稿 → 校验与差异 → 保存草稿
    → 试运行 → 选定运行反馈 → 修改 → 手动评测 → 发布
    → 网页使用 / API接入 → 查看产物、用量和账单

AI 编辑是平台基础功能,不是用户需要管理、分享或发布的业务智能体。
第一阶段只生成或修改配置,选择已有 Skills/MCP。不生成技能包、脚本或自动部署外部服务。

## 模型能力目录

| 能力分类 | 输入/输出 | 可采用的计量维度 |
| --- | --- | --- |
| LLM | 文本生成、图片理解、结构化结果 | 输入/输出 token,缓存读取/写入;图片输入按供应商实际用量归一 |
| 生图 | 文本或参考图 → 图片 | 张数、尺寸、质量档,或供应商提供的 token 用量 |
| 生视频 | 文本/图片 → 视频 | 时长、分辨率、质量档,或供应商返回的计量 |
| 语音生成 | 文本 → 音频 | 字符、音频时长或 token |
| 语音理解 | 音频 → 转写/理解结果 | 输入音频时长、token 或供应商实际计量 |

图片理解属于多模态 LLM,与生成图片的能力区分。
积分是统一结算单位,不是强行把所有能力转换成虚构 token。
目录项应记录能力类型、供应商适配类型、实际模型标识、输入限制、支持格式、价格版本与启停状态。
别名和展示名称可以调整,历史用量须保留实际模型与当时价目。

平台维护能力目录及服务端凭证;AI 编辑只能选择账号可用的能力,不能随意注册新供应商地址。
已有 MCP 与平台模型能力是两个不同来源:不是所有 MCP 都属于平台收费模型。

## 算力来源与收费规则

- 平台 AI 编辑:固定平台凭证,费用归当前账号的平台积分/套餐。
- 业务智能体的所有模型调用使用平台凭证,按实际模型和能力计量收费。
- 不支持账号自带模型 Key 或自定义网关;历史凭证及请求覆盖不再参与执行。
- 一次智能体任务可能包含 LLM、生图、视频等多种平台调用,分别计量后汇总。
- 对外系统的集成 API Key 仍保留,它用于访问本平台,不是供应商模型凭证。
- 不在未知价格、未知用量的情况下默认按零元结算。

账号先作为计费主体,后续团队租户可再引入独立计费账户。
这与文件读取隔离是两件事,计费主体分开不代表完成多租户安全隔离。

## 统一调用与账务层次

一次 run 可能产生多个模型调用,不能把 run 等同于一笔供应商请求。

    会话/任务(run)
        → 主 LLM 调用
        → 子代理 LLM 调用
        → 平台生图/视频/语音调用
            → 每次调用的用量事实、价格快照、凭证来源
            → 积分账务流水

核心记录:
- Run:沿用现有运行生命周期、输入输出、归属与审计。
- CapabilityCall:一次实际供应商调用的 ID、父 run、能力、模型、来源与结果状态。
- Usage:可核对的计量事实,区分增量与累计,去重缓存与子代理计量。
- Wallet/Ledger:积分余额、预占、扣减、释放、退回,只追加流水。
- Price/Package:价格版本、充值积分包和周期套餐。
- Order:充值订单、支付确认和到账幂等。

异步生视频等任务需要记录供应商任务 ID,平台重启后查询原任务,不重新付费提交。
取消供应商任务未必退费;按实际用量结算,不把业务取消直接当成账务退款。
初期实现显式适配器,不建设让用户编写任意 HTTP 请求模板的计费 DSL。
支付需选定渠道、商户配置后接通;未接支付时只允许明确标记的管理员入账,不能伪造支付成功。

## 页面与管理

用户侧:
- 智能体:创建、AI 编辑、配置、试运行、评测和发布。
- 工作台:业务会话、工具过程、审批、产物。
- 模型能力:展示可用能力、输入规格、来源与积分单价。
- 账户:积分余额、套餐、充值与消耗记录。
- 接入中心:智能体 API、Key 与 Webhook。

管理员侧:
- 模型和能力目录、平台凭证、价格版本。
- 套餐与人工入账、订单、账务核对。
- 账号、权限、额度、使用限制和审计。

设计会话单独列示,用量可追溯但不混入普通业务会话。
运行开始前显示平台模型及计价,多能力任务分别列明用量,不提供误导性的“免费模式”。

## 智能体市场

市场是核心入口,不是把后台智能体管理列表公开:
- 展示已发布、已上架、调用方有权使用的智能体;私有系统执行器不出现。
- 提供搜索、基础分类、用途、输入输出、所用能力和积分计价说明。
- “使用”进入已发布版本的 Web 对话;B 端可进入接入中心获取调用示例。
- “定制”必须明确复制权限,不默认公开作者提示词、技能源码或 MCP 凭证。
- 作者保存草稿不影响市场版本,上架/下架与版本发布关联。
- 第一版先做平台管理的精选市场,不加入复杂创作者分成、评分反作弊或广告推荐。
- 对外开放前完成必要的租户读取隔离;市场上线不代表可以忽略共享 HOME 的已知边界。

中期:部门/团队额度、空间(智能体、资料、成员放在一起)、图片/视频/语音能力接入、

欠款核销(只自动补扣)、知识库改为账号级。

## 验收原则

每项完成后更新本清单,保留实际验证结果与未覆盖内容,本地提交后再进入下一项。
外部供应商、支付渠道等缺少必要配置时完成可测试的接线与明确的未配置状态,
不得用假结果宣称真实服务已经接通。
涉及真实付费模型或支付时,按实际授权范围执行;测试默认使用模拟供应商与专用测试库。

详细 LLM 计费规则见 `2026-10-14-billing-design.md`;本文件新增的多模态和混合调用规则优先。
