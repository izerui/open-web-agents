# coze-v3 设计 spec（三个方向的共同输入）

## 项目

Open Web Agents：一个搭建、评测、发布、接入 AI 智能体，并在市场里使用智能体的平台（自部署，中文界面）。上一轮落地的是 JetBrains 深灰「B 对象工作区」，用户评价「交互不友好，不好看，体验差，比不上人家官方产品」。这一轮信息架构、导航骨架、色板、视觉风格全部可推倒重来，风格参照扣子（Coze）。

必读：
- `features.md`：从代码盘点的完整功能清单（功能一个都不能漏）
- `information-architecture.md`：新的信息架构、构建页五阶段、旧路由映射——三个方向都必须遵守功能归属，差别在导航骨架与交互形态
- `product-facts.md` 与 `refs/`：扣子的真实界面截图

## 受众与场景

| 用户 | 主要任务 | 设备 |
| --- | --- | --- |
| 构建者 / 开发者 | 新建、编排、评测、发布、接入 API、看运行记录 | 桌面为主 |
| C 端使用者 | 在市场找智能体、直接对话、管理积分和套餐 | 桌面与手机各半 |
| 平台管理员 | 账号、模型与提供者、市场上架、套餐、计费、审计 | 桌面 |

## 核心信息（每个方向都要让人一眼感到）

1. 建一个智能体是一条顺的路：新建 → 编排 → 评测 → 发布 → 接入，每一步都知道下一步在哪，不用手动保存、不用开新标签、不用跳到设置里。
2. 用一个智能体像用 App：市场像应用商店，点开就能聊。
3. 管理端是干净、密度适中的表格与详情抽屉。

## 情感基调

现代、利落、友好、可信。像官方产品，不像开源后台。不要 IDE 味，不要深灰。

## 输出格式（三版统一，否则没法横比）

- 每个方向一个单文件 `dir-N.html`（可读性优先，纯 HTML/CSS/原生 JS，或 React＋Babel inline；不要外部本地 js 文件；网络字体可用 Google Fonts）
- 文件顶部一条细的「页面切换条」（不属于产品界面，原型导航用），列出本方向的全部代表页，点击切换；默认显示第一页
- 桌面代表页画在 1440×900 画板里（可以内部滚动）；移动端画在 375×812 的手机框里，可并排 2 台
- 必须有的代表页（4～6 个）：
  1. **探索 / 市场首页**（C 端，桌面）
  2. **智能体构建页 · 编排**（含常驻预览与调试，桌面）
  3. **主流程演示**：同一个智能体从「新建弹层 → 编排 → 评测 → 发布（上线清单）→ 接入（签 Key、复制代码、试调）」，必须**真的能点着走完**：每一步有明确的「下一步」，阶段状态随操作变化（例如运行评测后用例逐个变绿、发布后版本号 +1、接入阶段出现一次性 Key）。可以是多个画面，也可以是同一画面里的阶段切换
  4. **平台管理**（桌面，账号表格＋详情抽屉，或模型与提供者）
  5. **移动端**：至少 2 屏——市场/智能体详情、对话（含工具调用摘要与提问卡片），可再加一屏「构建进度 / 发布」
  6. （可选）**对话工作台**桌面：会话列表、对话、工作区文件或执行详情、审批条
- 导航骨架里要能看出全部一级空间（探索、对话、工作室、开发者、账户、平台管理）与账号积分入口

## 演示内容（三版共用，用真实感中文，不用 Lorem）

主角智能体：**报销审核助手**（id `expense-reviewer`）
- 描述：读取发票和报销单，按公司制度做初审，超额提醒审批
- 提示词节选：「# 角色 你是公司财务的报销初审员……## 规则 1. 单笔超过 5000 元需要部门负责人审批 2. 发票抬头必须是公司全称『星河数据科技有限公司』3. 外币按开票日汇率换算」
- 模型：`claude-sonnet-4-5`（输入 300 / 输出 1500 积分每百万 token），最大轮次 20
- 能力：工具 Read, Grep, WebFetch；技能包 `invoice-ocr`（识别发票字段）、`policy-lookup`；MCP `erp-finance`（http，https://erp.example.com/mcp，已连通，12 个工具）；子代理 `currency-converter`
- 知识：《差旅报销制度 2026 版》.pdf 18 页 1.2 万字、《发票抬头规范》.docx、《常见问题》手动添加；检索测试「打车费能报吗」命中 3 段
- 变量：`ERP_TOKEN`（密钥、必填）、`DEPT`（部门）
- 契约：输入 `{ invoice_url, amount, currency }`，输出 `{ verdict: "pass|reject|need_approval", reasons[] }`
- 审批：权限模式「询问权限」；需审批工具 `erp-finance.submit`；无人值守「按入口默认」
- Webhook：https://hooks.xinghe.example/owa（投递 3 条，1 条失败可重发）
- 评测用例 6 个：超额需审批、抬头不全应拒绝、外币换算、多张发票合并、餐饮超标准、正常差旅放行；初始 4/6 通过，修复后 6/6
- 版本：已发布 v3（10-28），草稿有 4 处未发布修改；发布后变 v4
- 接入：`POST /api/agents/expense-reviewer/invoke`，curl / Python / Node 三段代码，Key 前缀 `owa_live_`

市场其他智能体（8 个左右，分类：通用助手、研究分析、内容创作、开发工具、办公运营）：会议纪要整理、竞品周报、代码审查员、SQL 助手、小红书文案、合同条款比对、客服知识问答、周报生成器。每个有作者、vN、单价「约 2 积分/次」类描述、使用次数。

账号与计费：当前用户 林舟（linzhou@xinghe.example，普通账号），积分 12,480 可用、冻结 120；管理员 周岚。平台 24 个账号、21 个启用、本月消耗 38.6 万积分。提供者：Anthropic 官方（已配置，6 个模型）、内网代理（OpenAI 兼容，3 个模型）。

## 已知约束（业务规则，不能画错）

- 发布要求：对当前草稿的评测全部通过（至少 1 个用例），且之后没改过配置或用例；回滚、设为发布版不受评测限制
- 未发布时调用和他人使用都跑草稿；发布后他们用发布版，调用方可用 `version` 锁版本
- 公开（只读给所有账号）≠ 上架市场；上架由管理员操作
- Key 明文只显示一次；轮换后旧 Key 24 小时内仍有效
- 每个评测用例真实调用一次模型、计费
- 会话是私有的，管理员也看不到别人的会话
- 可读性底线：正文 ≥14px（移动端 16px）、标签 ≥12px，正文对比度 ≥4.5:1，可点元素 ≥44×44（移动端）

## 图片需求

不用 stock 照片。智能体头像程序化生成（色块、字母或几何、卡通眼睛均可，按方向定），每个智能体一种，市场与会话里一致。
