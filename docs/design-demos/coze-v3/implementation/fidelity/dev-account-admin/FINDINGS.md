# 还原度排查 · dev-account-admin（开发者 / 账户 / 平台管理 / 手机「我的」「登录」）

产品 5678 用 design-review 普通账号（会话 fid4u），5679 是本地模式管理员（会话 fid4a）。原型另开了一个会话 fid4p 用 file:// 打开。本机没有运行、流水、运行消耗、用量、上架申请这些数据，这几页用 playwright `page.route` 塞了模拟数据来核对，图名带 `-mock`。

## 开发者 · API Key 与签名密钥
- **F-01（中，效果缺失）Key 列表只显示内部 ID，不显示 Key 尾号。**
  - 原型：名称下面显示 `owa_live_••••7Q2c`，明文框写「关掉后只能看到末尾 4 位」，确认框里也带这串掩码。
  - 产品：显示 `ID 9d5d30bbfe56`，确认框里没有 Key 标识。轮换后新旧两行同名，用户拿着明文对不上是哪一行。
  - 图：`dev-keys-issued.png`、`dev-keys-rotated.png`、`dev-keys-revoke-confirm.png`
  - 代码：`src/features/integration/developer-keys-view.tsx:433`，轮换确认在 `:494`
  - 建议：存下前缀和末 4 位，列表和确认框都显示。
- **F-02（低）轮换后旧 Key 那一行没标「（旧）」。**
  - 原型的标签是「轮换后旧 Key，24 小时后失效」，产品只显示通用的「24 小时后过期」。
  - 图：`dev-keys-rotated.png`
- **F-03（中，交互不同）表单校验弹浏览器原生气泡，不是行内红字。**
  - 产品输入框带 `min=1` 或 `required`，浏览器先拦下提交，弹出「值必须大于或等于 1」这类气泡；英文浏览器下是英文。组件自己写的红字报错永远显示不出来。
  - 同样的问题在：`key-rate-limit.tsx:109-116`、`account-security-view.tsx:67-90`、`login-form.tsx:140-175`
  - 图：`dev-keys-rpm-invalid-native-bubble.png`
  - 建议：form 加 `noValidate`。
- **F-04（低）每分钟上限的取值范围不一样。** 原型是 1 到 300，产品普通账号只能填 1 到 60，横幅里写的合计却是 600。如果是有意的规则，需要在表单里写明。
- **F-05（低）两处反馈问题。**
  - 点「我已保存」没有 toast，原型会提示「明文已隐藏，之后只显示末尾 4 位」（`developer-keys-view.tsx:336`）。
  - 签名密钥卡生成成功后，之前的输入报错红字还留着（`webhook-secret-card.tsx:27-40` 成功后没有清 inputError）。
- **F-06（中，全局）toast 位置和样式不同。** 原型是底部居中的深色胶囊；产品在右上角，会盖住右侧抽屉的标题和关闭按钮，375 宽下会盖住页面标题。
  - 图：`dev-runs-cancelled-toast-over-drawer.png`
  - 建议：改成 `bottom-center` 加深色。

## 总结
整体还原度约 78%。开发者 Key 与签名密钥、账户各页、账号与用户组、提供者和模型弹窗、上架审核这几块基本照原型做了。差距集中在四处：平台运行缺少「谁跑的」，计费管理页的版式和批量发放流程，手机端的导航结构，以及数字格式和操作反馈的细节。

最该先修的 5 条：
1. **F-33**：平台运行没有账号列、账号筛选，抽屉里也没有账号。
2. **F-35**：手机上没有底部标签栏和「我的」聚合页。
3. **F-11 + F-07**：流水显示 6 位小数，运行记录又用美元，账对不上。
4. **F-23 + F-21**：别名映射保存没有确认，加价越界没有实时提示，都是影响全平台的操作。
5. **F-29 / F-30 / F-31**：计费管理的概览、账户页签和批量发放，管理员最常用的发积分流程和原型差得最多。
