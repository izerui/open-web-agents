# 构建页（build）还原度排查

范围：原型 `prototype/build.html`（shots/build-*.png 共 18 张）↔ 产品 `/agents/<id>?stage=…`、`/agents/new?designer=…`。5679 本地模式（会话 `fid3a`）编辑 `/agents/default`；5678 用 design-review 看只读视图（会话 `fid3u`）。

对照图都在本目录：`build-<状态>.png` 是左原型、右产品；文件名以 `-product.png` 结尾的是只有产品截图的状态。

## 一、主流程连贯性（从工作室「用智能体设计器创建」走到接入）

实际走了一遍：工作室 → 新建弹层 → 「用设计器创建」→ `/agents/new?designer=…` → 发送（本机失败，后续用模拟数据）→ 应用到草稿 → 试聊 → 存为用例 → 评测 → 让设计器修复 → 上线清单 → 发布 → 接入签 Key → 试调。

卡顿点：
1. 弹层里写好的描述落地后不会自动发出，设计器显示通用空状态，还得再点一次发送（F1）。
2. 设计器给出改动后，对话被待确认改动面板挤到只剩 100–150px；应用后对话里不留痕迹，也没有「下一步」按钮（F2、F3）。
3. 试聊里存好用例只弹一个 toast，没有「去评测」入口（F3）。
4. 评测跑完，结果不会回传给设计器；好在评测横幅有「让设计器修复」和「去上线清单」。
5. 上线清单 → 发布成功卡「去接入」→ 签 Key、看代码、试调：这一段和原型一致，很顺。
6. 新建时右侧默认展开两节，名称框一上来就是红字报错（F12）。

## 二、发现清单

**F1 新建：设计器描述不自动发送**
- 页面：`/agents/new?designer=…`（对照图 build-new-ai.png）
- 原型：自动发出描述，设计器立刻给出带推荐项的提问卡片。
- 产品：描述只预填进输入框，要再点一次发送。
- 类别：交互不同。严重度：**高**。
- 代码：`src/app/agents/new/page.tsx:18-30`、`src/features/build/use-designer.ts:94`。
- 建议：会话还没有任何轮次且带了 `desc` 时，自动 `send` 一次，发完从地址里去掉 `desc`；不想自动扣费的话，至少把空状态改成「已填好你的描述，按发送开始」。

**F2 设计器：待确认改动面板挤压对话，改动和对话脱节**
- 页面：编排 · 设计器（build-designer.png、build-designer-applied-product.png）
- 原型：差异卡片嵌在对话流里；应用后原地变成「已应用到草稿」，选「先不改」变成「没有应用」，历史里一直看得到。
- 产品：所有改动集中在对话下方一个最高占 55% 高度的面板里，900 高的屏幕上对话区只剩 100–150px；应用或先不改之后，改动直接从界面消失。
- 类别：布局 / 交互不同。严重度：**高**。
- 代码：`designer-panel.tsx:256-340`、`:510-580`。
- 建议：把改动卡片放到触发它的那一轮回复下面（可以用 ChatThread 的 `renderTurnExtra`），或者面板默认收起成一行；处理后在对话里留一条状态。

**F3 阶段之间缺少「下一步」引导**
- 原型：设计器在每个节点主动跟一条带按钮的消息——试聊一条 / 看评测、重新运行评测、去评测、修复这 2 个、打开上线清单、去接入。
- 产品：全都没有。应用后只有 toast「已应用到草稿：提示词」，存用例只有 toast，评测结果不回传给设计器。
- 类别：效果缺失。严重度：**高**。
- 代码：`build-page.tsx:181-194`、`trial-panel.tsx:326-331`、`eval-stage.tsx:161-167`。
- 建议：在设计器底部加一条前端生成的提示条（不调模型），按事件显示下一步按钮。

**F4 有待确认改动时，「试运行反馈」面板看不到**
- 产品：反馈列表渲染在待确认改动面板下面、同一个滚动区里。点按钮后屏幕上什么都没出现，要往下滚才看得到。
- 类别：可能的缺陷。严重度：中。
- 代码：`designer-panel.tsx:305-329`。
- 建议：把它放到改动面板前面并 `scrollIntoView`，或者改成浮层。

**F5 只读视图「克隆一份来改」点了必失败**
- 页面：5678 只读视图（build-readonly.png）
- 产品：按钮是可点的主按钮，点了 toast「克隆失败：只能克隆已上架到市场的智能体」。可编辑页「更多」菜单里的「克隆一份」也一样；工作室只读抽屉里同一个按钮却是禁用并有说明，两处不一致。
- 类别：可能的缺陷。严重度：**高**。
- 代码：`readonly-view.tsx:63`、`build-page.tsx:508,538`；服务端限制在 `src/app/api/agents/[id]/clone/route.ts:24`。
- 建议：先定规则。保持「只能克隆已上架的」就按 `marketListed && publishedVersion` 禁用并说明原因，只读说明文案也别再写「或克隆一份来改」；按原型放开就改服务端。

**F6 页头「编排 完整」徽标过早变绿**
- 产品：只要名称和提示词填了就显示绿色「完整」，档案卡同时写着「4/9 节已填」。原型是九节都填了才显示「完整」。
- 类别：视觉偏差。严重度：中。
- 代码：`build-model.ts:82-87`。
- 建议：没填满时显示「N/9 节」。

**F7 设计器「这一轮没有完成」没有重试按钮**
- 严重度：中。代码：`designer-panel.tsx:244-249`。
- 建议：加「重试」，重发上一轮的 prompt。

**F8 档案里删除技能包 / MCP / 子代理 / 变量没有确认**
- 产品：点垃圾桶就直接删，紧接着自动保存，没有撤销；原型每次都弹确认框。
- 严重度：中。
- 代码：`skill-editor.tsx:55`；`profile-card.tsx:585-592`、`736-743`、`867-874`。
- 建议：复用 `useConfirm`，或者删除后给一个可撤销的 toast。

**F9 删除智能体不要求输入 ID 确认**
- 产品：普通确认框，点一下就删；原型要输入 ID 才能删。
- 严重度：中。
- 代码：`build-page.tsx:364-384`、`publish-stage.tsx:486-505`。

**F10 Skills / MCP 来源：从「只读引用」变成「复制进来」**
- 原型：引用不复制，来源更新后跟着变，能力节里显示「引用自 X，只读」。
- 产品：勾选后要经过设计器确认，应用时把内容复制进本智能体；没有设计会话时，加来源会悄悄新建一个。
- 类别：交互不同。严重度：中。
- 代码：`design-sources.tsx:63-66`、`use-designer.ts:544-578`。
- 建议：如果复制是后端限制，就在 gaps 里登记为有意偏差，给复制进来的条目标来源，并在新建会话前提示。

**F11 知识节沿用旧 Builder 的知识面板**
- 产品：卡片套卡片；手动添加是一直摆着的表单；没有篇数进度条；文案是半角标点。
- 严重度：中。
- 代码：`profile-card.tsx:247-256`、`builder/knowledge-panel.tsx`。

## 三、核对过、和原型一致的部分
- **页头**：保存状态的各种情况（保存中、已保存于、暂停原因可点跳转、别处修改、保存失败重试）、五阶段徽标、上线清单按钮。
- **设计器**：深色头、差异与保存角标、展开成主画面并显示档案大纲与「刚更新」高亮、收起成竖条、设计记录切换与新建、空状态、提问卡片（倒计时 / 多选 / 其他 / 不回答）、冲突 / 旧设计 / 出错三态、待确认时锁住切换、差异与保存弹层的禁用逻辑。
- **档案九节**：字段与校验齐全，暂停保存的原因可以跳到对应的节。
- **评测**：横幅五态、运行目标、逐个转圈、失败默认展开、让设计器修复、确认框里的积分预估、用例表单。
- **发布**：清单逐项出现、去处理 / 去修复 / 查看差异、发布成功卡与去接入、版本各操作与对比弹层、公开、申请上架、按账号或组分享与撤销。
- **接入**：徽标、OpenAPI、签 Key（一次性明文）、轮换 / 吊销、代码三页签、在线试调、Webhook 签名密钥与投递记录。

## 四、总结

整体还原度约 **78%**。最该先修的 5 条：
1. **F2**：待确认改动放回对话流（或默认收起），处理后在对话里留痕迹。
2. **F1**：带着描述进来时自动发给设计器，或者明确提示按发送开始。
3. **F3**：加「下一步」引导条——应用后去试聊 / 评测，存用例后去评测，评测完去上线清单或请设计器修复。
4. **F5**：只读视图的「克隆一份来改」和服务端规则对齐。
5. **F6 + F8**：「编排完整」只在九节填满时变绿；档案里删除条目加确认（F9 删除智能体要求输入 ID 可以一起做）。
