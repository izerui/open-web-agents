# 原型还原度排查 · 共同简报

目标：逐页对照「原型」与「已实现的产品」，找出交互和效果上没达到原型预期的地方。**只排查、不改代码**（发现问题写清楚，修复由协调者统一做）。所有输出用中文。

## 两边各在哪里
- **原型**（标准答案）：`docs/design-demos/coze-v3/prototype/<页面>.html`，用 `file://` 打开；视觉数值见 `prototype/assets/owa.css`；已有截图在 `prototype/shots/`。原型左下有「新增功能标注」开关（不属于产品）。
- **产品**（生产构建，已在运行，不要停）：
  - `http://localhost:5678` —— 正常登录，普通账号 `design-review@example.test` / `design-review-123`
  - `http://localhost:5679` —— 关闭登录的本地模式（匿名管理员，能编辑内置的「通用智能体」`/agents/default`）。**浏览器里不能带 5678 的登录 cookie**，用单独的 agent-browser 会话
- 设计依据：`docs/design-demos/coze-v3/information-architecture.md`、`features.md`、`gaps.md`
- 本机限制：开发库没开 Redis、账号没有积分，凡是要真跑模型的地方（对话回复、设计器回复、试聊、评测运行、在线试调）会失败。这些状态请用 playwright 拦截接口塞模拟数据（`npx playwright` 或 node 脚本 + `page.route`）来核对界面效果，或者明确标注「无法在本机验证」。**不要往库里写测试数据以外的东西；不改任何账号；自己造的数据用完删掉。**

## 怎么对照（每个页面都做）
1. 1440×900 下打开原型页与产品页，各截一张，拼成左右对照图存到 `docs/design-demos/coze-v3/implementation/fidelity/<你的区域>/`（文件名 `<页面>-<状态>.png`）。
2. 逐个走原型里的交互：点每个按钮、页签、展开、弹层、抽屉、下拉、提示、键盘操作（回车发送、Esc 关闭、⌘K），对比产品里同一个动作的结果：有没有、去哪了、反馈是否一样（toast、动画、高亮、状态徽标变化、数字变化、空态/加载/错误态）。
3. 375×812 宽度下再看一遍关键页。
4. 判断标准：**功能等价 + 效果接近**。数据不同（原型是演示数据）不算问题；文案小差异不算问题，除非意思变了；产品比原型多出的合理能力不算问题。

## 每条发现的格式（写进 `fidelity/<你的区域>/FINDINGS.md`，并在最终回复里给出全文）
- 编号、页面与状态、原型里是什么样、产品里是什么样、对照图文件名
- 类别：交互缺失 / 交互不同 / 效果缺失（反馈、动画、状态变化）/ 视觉偏差 / 布局 / 文案 / 可能的缺陷
- 严重度：高（用户会明显感到「不是那个设计」或流程卡住）/ 中（细节不到位但能用）/ 低
- 涉及的产品代码位置（尽量给出文件:行号，方便修）
- 建议怎么改（一两句）

最后给一个总结：这个区域整体还原度（百分比估计）和最该先修的 5 条。
