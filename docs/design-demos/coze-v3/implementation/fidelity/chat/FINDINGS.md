# 对话页（chat）还原度排查

对照：原型 `prototype/chat.html`（正常 / 运行中 / 空会话 / 无智能体 / 读取失败 / 智能体不存在，以及 `?session=s4`、`?session=s5`）↔ 产品 `/chat`（5679，接口全部模拟）。

## 高

**F1 对话正文里指向工作区文件的链接显示成「[blocked]」**
- 页面/状态：正常，第 3 轮「已写好两个文件」。
- 原型：`初审结果.md` 是链接，点了右侧切到「工作区文件」并预览这个文件。
- 产品：智能体写的相对路径链接 `[初审结果.md](初审结果.md)` 被 Streamdown 的链接安全检查拦下，显示成「初审结果.md [blocked]」，点不了。375 宽下也一样。
- 对照图：`chat-normal.png`、`chat-files-md.png`、`chat-mobile.png`
- 类别：可能的缺陷 / 交互缺失
- 代码：`src/components/ai-elements/message.tsx:276-283` 没配链接白名单，也没有自定义链接渲染；对话里在 `conversation.tsx:983` 调用。
- 建议：给对话里的 MessageResponse 加自定义链接渲染。不带协议的相对路径当工作区文件处理，点了打开文件面板并预览；http(s) 外链照常放行。

**F2 「智能体在问你问题」的常驻通知挡住对话头（桌面和 375 宽都会）**
- 原型：提问只在对话里的卡片上出现，没有浮层通知。
- 产品：右上角的提示一直挂着，不会自己消失，正好盖住「工作区文件 / 执行详情」开关。375 宽下盖住整条对话头，包括会话列表按钮。审批通知在窄屏下有意不弹，提问通知没做同样处理。
- 对照图：`chat-ask.png`、`chat-mobile-ask.png`
- 类别：布局 / 可能的缺陷
- 代码：`approval-bar.tsx:189-196`，提问分支在第 200 行的窄屏判断之前就跳过了。
- 建议：提问通知改为几秒后消失，或者只在卡片不在视口、页面不可见时才弹；窄屏一律不弹。

## 中

**F3 停止运行没有确认弹窗**
- 原型：点停止先弹「停止这一轮？」，说明已生成的文件会保留、排队中的 N 条不会发送；确认后 toast「已停止」。
- 产品：点了直接请求停止，没有确认，也没有 toast，只在那一轮末尾出现「已取消」卡片。
- 对照图：`chat-prod-running-stopped.png`
- 类别：交互缺失
- 代码：`workbench.tsx:1303`、`composer.tsx:264-273`
- 建议：加确认弹窗，文案照原型，有排队消息时写上条数。

**F4 运行在等审批或等回答时发消息，产品直接追加（steer）**
- 原型：等你确认时，新消息进排队区，toast「已排队，本轮结束后发送」。等你回答提问时不发，toast「先回答或选择不回答」，文字留在输入框。
- 产品：两种情况都直接追加给运行中的智能体，toast「已交给智能体」，排队区不出现。
- 对照图：`chat-running.png`、`chat-ask.png`（以实测日志为准）
- 类别：交互不同
- 代码：`workbench.tsx:865-881`
- 建议：有待确认的工具时改为排队，有待回答的提问时拦下并提示。

**F5 没填必填变量也能发送**
- 原型：发送前 toast「先填写必填变量 ERP_TOKEN」，并直接打开「填写变量」弹窗。
- 产品：照常先建会话再发起运行，失败后出一张「这一轮失败了」卡片，内容是「Error: 发起运行失败:…」，多了英文前缀 `Error:`。顺带留下一个空会话。
- 对照图：`chat-prod-empty-send-novars.png`、`chat-empty.png`
- 类别：交互缺失
- 代码：`workbench.tsx:634-637` 发送前不看变量状态；`variable-prompt.tsx:69` 的缺失变量信息没往外传；`workbench.tsx:717` 直接用了 `String(error)`。
- 建议：把缺失变量的状态提到 Workbench，发送前拦下并打开弹窗；错误摘要改用 `error.message`。

**F6 文件树点目录名不展开**
- 原型：目录的子项直接列在树里。
- 产品：点目录名没有任何反应，只有点左边的小箭头才展开（代码里有意忽略了目录名的点击）。
- 对照图：`chat-normal.png`（默认全收起）、`chat-files-pdf.png`（展开后）
- 类别：交互不同
- 代码：`file-panel.tsx:453-458`
- 建议：点目录名时切换展开状态。

**F7 会话列表只给当前打开的会话标「待你确认 / 等你回答」**
- 原型：任何在等你的会话都标黄色「等你回答」，没打开的也标。
- 产品：别的会话只有转圈，没有等待标签，用户看不出是哪个会话在等自己。
- 对照图：`chat-normal.png`（左栏「外币发票汇率」）
- 类别：效果缺失
- 代码：`session-list.tsx:82-91`
- 建议：列表接口按会话带回待确认、待回答的计数，行上据此标出。

**F8 375 宽下审批卡加授权条把对话流挤没了**
- 产品：审批卡的按钮竖排，再加「本会话已授权」条，占满对话头和输入框之间的全部空间，对话内容一行都看不到。
- 对照图：`chat-mobile-prod-panel-approval.png`（右半）
- 类别：布局
- 代码：`approval-bar.tsx:283`（最大高度 50vh 在小屏上不够收）、`approval-bar.tsx:236-256`（授权条）
- 建议：窄屏下审批卡默认收成一行（标题、倒计时、批准、展开），参数摘要折叠；授权条收进卡片里。

**F9 首次进入时右侧面板默认关闭**
- 原型：默认打开「工作区文件」，并预览最新生成的 md 文件。
- 产品：没有本地记忆时面板关着，打开后也不会自动预览任何文件。
- 对照图：`chat-normal-default.png`
- 类别：交互不同
- 代码：`workbench.tsx:255-260`
- 建议：桌面端没有记忆时默认打开工作区文件；可以再按修改时间自动选中最新的 md 或 html。

**F10 审批批准或拒绝后没有反馈 toast**
- 原型：有「已批准」「已拒绝」「已拒绝，原因已交给智能体」「确认超时，已自动拒绝」。
- 产品：只有「批准，本会话内不再询问」有 toast；普通批准、拒绝、拒绝并说明都没有反馈，卡片要等下一次轮询才消失。
- 类别：效果缺失
- 代码：`approval-bar.tsx:155`
- 建议：按操作分别弹 toast，并立即从本地待确认列表里去掉这张卡。

**F11 工具调用摘要退化成参数名，也没有耗时**
- 原型：每行写这次调用在做什么（如「确认审批人规则」），右边是耗时。
- 产品：工具输入里没有说明字段时，显示的是参数名，比如「dept, month」「invoices, approver」；没有耗时。执行详情面板也一样。
- 对照图：`chat-running.png`、`chat-stream-top.png`
- 类别：视觉偏差 / 效果缺失
- 代码：`conversation.tsx:115-128`、`run-tree.tsx:157-159`
- 建议：没有说明字段时，取第一个字符串参数值（如 query、url、path）的前 60 个字作摘要；事件带时间戳的话，补上耗时。

**F12 工作目录清理时间跟随浏览器语言格式**
- 产品：显示「11/11/2026, 12:00:56 AM」（测试浏览器是 en-US）；原型是「11-10 03:00」。
- 对照图：`chat-purged.png`
- 类别：文案
- 代码：`workbench.tsx:1105`
- 建议：用固定的 `MM-DD HH:mm` 格式。

## 对上的部分

下面这些和原型一致或更好：

- **左栏**：会话三段分组与搜索；「…」菜单（重命名 / 归档 / 删除，删除确认文案一致）；已归档视图与恢复（有 toast）；设计器会话的标签和跳转地址。
- **对话头与对话流**：
  - 头像、名称链接、版本和运行中徽标、两个开关；变量条。
  - 轮次导航与「回到最新」；工具卡的失败、进行中计数。
  - 点工具调用后在执行详情里定位并闪烁。
  - 结构化结果、失败、取消卡片；token、复制和重跑弹层。
- **提问与审批**：
  - 提问卡片：待回答倒计时、多选加「其他」。
  - 审批条：倒计时、30 秒内变红、四个操作。
  - 授权条与撤销；排队列表。
- **输入框**：上下文用量环；斜杠命令（方向键加回车，/search 能打开命令面板）；拖放覆盖层的样式。
- **右侧面板**：拖宽（16%–45%）、关闭；Markdown 预览与源码、代码高亮、图片、二进制下载、过长截断提示；工作区不存在的提示。
- **375 宽**：会话列表抽屉和右侧面板抽屉。

## 总结

整体还原度约 82%。布局、视觉和主要流程基本到位，差距集中在运行中的交互细节和反馈上。

最该先修的 5 条：
1. **F1**：对话里的文件链接显示「[blocked]」，「生成文件后点开看」这条主流程断了。
2. **F2**：提问的常驻通知盖住对话头，窄屏连会话列表按钮都挡住。
3. **F5**：没填必填变量也能发送，结果是一张失败卡片加一个空会话。
4. **F4 + F3**：等审批或等回答时发消息直接追加，和原型的排队、拦下不一致；停止没有确认。
5. **F6**：文件树点目录名不展开；同批可以顺手修 F8（窄屏审批卡把对话流挤没）。
