# 信息架构 v3（coze-v3）

依据：`features.md`（从代码逐页盘点出的完整功能清单）。本文件定「东西放在哪」，三个视觉方向都遵守它；方向之间的差别在导航骨架和交互形态，不在功能归属。

## 1. 现在的问题（来自 features.md 第 4 节的事实）

1. 一条「新建 → 接入」链路跨 2 个页面（`/agents`、`/settings/keys`）、Builder 内 4–5 个 tab、至少 2 次手动保存；走 AI 编辑再多 1 个页面。
2. 「先保存」闸门：知识、评测、发布三个分区在首次保存前全部不可用。
3. 试运行在新浏览器标签打开工作台；试运行结果在 Builder 里看不到，也不能直接变成评测用例。
4. Webhook 地址在「安全与契约」，投递记录与签名密钥在接入中心，「配置回调地址」又落到「配置」tab。
5. 接入中心挂在「账号设置」下，而不是智能体自己的页面里。
6. 发布区写「在下方评测里添加用例」，评测其实在前一个 tab；公开 ≠ 上架，上架没有申请入口。
7. 用量 / 积分 / 套餐 / 模型价格分散四页；运行记录、用量明细、运行消耗各列一次运行。
8. 有 API、无 UI：取消运行、恢复归档会话、版本快照查看、在线试调 invoke。

## 2. 对象模型

```
账号（admin | user）
 ├─ 智能体（我建的 / 分享给我的 / 市场里的）
 │   ├─ 草稿（自动保存）──评测──▶ 版本 v1…vN（发布 / 回滚 / 载入草稿）
 │   ├─ 会话（对话、工作区文件、运行树、审批、提问）
 │   ├─ 运行（来源：工作台 / API / 接口调用 / 评测 / AI 编辑）
 │   └─ 接入（调用文档、Webhook 地址与投递记录）
 ├─ API Key（账号级，可限定智能体）  ·  Webhook 签名密钥（账号级）
 └─ 积分账户（余额、冻结、流水、订单、用量）
```

## 3. 一级空间（按角色）

| 空间 | 给谁 | 内容 | 默认落点 |
| --- | --- | --- | --- |
| **探索** | 所有人（C 端主场） | 市场首页、分类、搜索、智能体详情、「立即使用 / 克隆 / API 接入」 | 市场首页 |
| **对话** | 所有人 | 会话列表（按智能体分组、含归档）、对话、工作区文件、执行详情、审批、提问、变量 | 最近会话或新会话 |
| **工作室** | 构建者 | 我的智能体（含分享给我的）、新建、单个智能体的构建页 | 我的智能体 |
| **开发者** | 构建者 | API Key、Webhook 签名密钥、全部运行记录 | API Key |
| **账户** | 所有人 | 积分与套餐（余额、充值订单、流水、运行消耗）、用量分析、模型价格、账号安全、操作日志 | 积分概览 |
| **平台管理** | 仅 admin | 账号、模型与提供者、市场上架、套餐与订单、计费（概览/账户/对账）、平台用量、平台运行、平台审计 | 账号 |

C 端用户只看到「探索 · 对话 · 账户」三项；新建过智能体后「工作室」「开发者」才出现在主导航（之前收进「更多」）。管理员额外看到「平台管理」。

## 4. 单个智能体的构建页（主流程的核心）

一页、一份自动保存的草稿、五个阶段，阶段之间用同一条顶栏切换，预览对话常驻：

| 阶段 | 包含（features.md 对应分区） | 进入下一阶段的条件 |
| --- | --- | --- |
| **编排** | 名称/头像/描述/开场建议 · 提示词 · 模型/最大轮次/推理强度 · 能力（工具白名单、技能包、MCP、子代理）· 知识（上传/手动/检索测试）· 变量与密钥 · 输入输出契约 · 审批与权限 · Webhook 地址；右侧常驻「预览与调试」 | 名称与提示词非空（自动保存，无保存按钮） |
| **评测** | 用例列表与编辑 · 从预览对话「存为用例」· 运行评测（选草稿或 vN）· 历史与详情 | 当前草稿全部通过 |
| **发布** | 上线清单（编排完整 / 评测通过 / 有修改可发布）· 版本说明 · 发布为 vN · 版本列表（回滚、设为发布版、对比、载入草稿）· 公开 / 申请上架 · 定向授权 | 至少有一个发布版（未发布时调用用草稿，照原规则） |
| **接入** | 本智能体的调用文档（curl/Python/Node、OpenAPI）· 在线试调 invoke · 签发限定本智能体的 Key（内联）· Webhook 地址＋投递记录＋签名密钥状态 | — |
| **运行** | 本智能体的运行记录与详情抽屉、分析（次数/失败率/消耗） | — |

**智能体设计器是亮点**（用户原话：「注意原有的 智能体设计器 要适配，这个功能是亮点」）。原 `/agents/design`（内置智能体 agent-architect 驱动）在新架构里是构建页编排阶段的主角，统一称「智能体设计器」，可展开成主画面。现有能力全部保留：设计记录切换与新建、提问卡片与审批、从试运行结果反馈、legacy / conflict 基线保护与「载入当前草稿」、校验问题、整体「差异与保存」（不创建发布版本）、从其他智能体引用 Skills / MCP 及同名冲突、高级参数 JSON 与禁用字段。新增按节应用改动（A4）与「让设计器修复」评测失败（A7）。

AI 编辑不再是独立页面，而是编排阶段右侧面板的第二个页签「AI 助手」：对话改草稿 → 显示差异 → 「应用到草稿」。原 `/agents/design` 的差异确认、冲突处理、试运行反馈全部保留在这个面板里。

## 5. 主流程（新）

| 步骤 | 新做法 | 解决的断点 |
| --- | --- | --- |
| 新建 | 一个弹层：「描述你想要的智能体」（AI 生成）或「空白创建」或「从模板/市场克隆」；确认后立即建好草稿并进入编排 | 5 个入口统一；不再先进列表；无首次保存闸门 |
| 配置 | 编排页一屏看全部能力行，点行展开就地编辑；右侧预览实时用草稿对话 | 不再切 4 个 tab；试运行不开新标签 |
| 评测 | 预览对话里每条回复可「存为评测用例」，自动带输入与期望；评测阶段一键运行 | 用例来源与配置在同一处 |
| 发布 | 顶栏常驻「发布」按钮，点开是上线清单；评测未通过时清单直接给「去修复」 | 发布门槛可见、不再在两个 tab 间来回 |
| 接入 | 发布成功后直接进入接入阶段：签发 Key（内联）→ 复制代码 → 在线试调 | 接入不再藏在账号设置 |
