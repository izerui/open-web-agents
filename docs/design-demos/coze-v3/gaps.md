# dir-2 设计与现有功能的差异清单

## 决定（2026-11-11）

用户原话：「现有产品没有的就补上呗。」

A1–A17 全部作为新功能纳入，原型按 dir-2 的设计完整呈现，不做降级。表中「可选的适配办法」一栏改作实现思路参考，取每行的第一种完整做法。
A15 一并补上：定向分享支持「账号」和「组」，需要同时恢复用户组的管理界面（API 已有 /api/groups）；这与之前「一个账号即一家企业」的取舍相反，实现前再确认一次影响。
页面左下的「差异标注」开关保留，用来标出这些新功能在哪里，方便后续排开发。

对照依据：`features.md`（代码盘点）与 `dir-2.html`。原型照 dir-2 的设计做，下表中的条目在原型里都会出现，并在页面上标注；是否实现、怎么适配由用户决定。

「需后端」= 现有 API 和数据都没有，要新做；「需改造」= 能力已有，但交互规则或流程要改；「需前端」= API 已有，只是 UI 没有入口。

## A. dir-2 有、现有产品没有的（需新做或改造）

| # | dir-2 里的设计 | 现有情况 | 类型 | 可选的适配办法 |
| --- | --- | --- | --- | --- |
| A1 | 探索首页大输入框「想交给它什么事」：输入一句话，推荐交给某个已上架智能体，或「让搭建助手做一个」 | 市场只有按名称/说明的关键词搜索，没有按意图推荐 | 需后端 | ① 先用关键词搜索＋固定「让搭建助手做一个」兜底；② 后续接模型做意图匹配 |
| A2 | 「你的 AI 同事正在工作」：跨智能体的最近会话，带「成果已交付 / 正在工作」状态和交付物文件卡 | 有会话列表和运行状态；没有「交付物」概念 | 需改造 | 状态取最近一次运行的状态；交付物取工作区里最新生成的文件，或者去掉文件卡 |
| A3 | 草稿自动保存，没有「保存」按钮 | 必须手动点「保存智能体」；知识、评测、发布要先保存一次才能用 | 需改造 | 字段失焦或停顿后自动 PUT 草稿；新建时立即创建草稿记录 |
| A4 | 搭建助手直接改草稿，右侧档案卡逐节「刚更新」高亮，改动用「应用到草稿 / 先不改」确认 | AI 编辑（/agents/design）是独立页面，改完要打开「差异与保存」确认整体保存，有冲突/基线检查 | 需改造 | 保留现有差异确认与冲突检查，粒度从整体保存改成按节应用；或者保持整体确认，只把 AI 编辑搬进构建页 |
| A5 | 构建页内「试聊」，直接用草稿对话 | 「试运行」是在新浏览器标签打开工作台 | 需改造 | 在构建页嵌入工作台的对话组件（同一个会话接口，source 标为试运行） |
| A6 | 试聊回复下方「存为评测用例」，预填输入和期望 | 评测用例只能在评测 tab 手填 | 需前端 | 从这一轮的 prompt 和回答预填用例表单，复用现有创建用例接口 |
| A7 | 评测失败项「让搭建助手修复」，助手给出 diff 再应用 | AI 编辑只有「从试运行结果反馈」，没有接评测失败 | 需改造 | 把失败用例的输入、输出快照、断言拼进搭建助手的提示，复用 A4 的应用机制 |
| A8 | 「上线清单」一页：编排完整 / 评测通过 / 有修改可发布 / 发布 / 接入，逐项变绿 | 发布约束已有（评测通过、有差异、无未保存），只是散在发布 tab 的文案里 | 需前端 | 用现有 release-status 接口的状态渲染清单；「编排完整」规则要定（建议：名称和提示词非空） |
| A9 | 运行评测确认框写「预计约 N 积分」 | 只提示「每个用例真实调用并计费」，没有预估 | 需后端 | 按用例数 × 该模型最近平均单次花费估算；或者去掉具体数字 |
| A10 | 市场卡片显示作者、使用次数（如「1.8 万次」） | 卡片只有名称、说明、类别、vN、模型单价 | 需后端 | 作者取所有者账号名；使用次数按运行表统计（要考虑性能，可每日汇总） |
| A11 | 价格写成「约 2 积分/次」 | 只有模型单价（积分/百万 token） | 需后端 | 按该智能体最近 N 次运行的平均花费算；没有数据时显示模型单价 |
| A12 | 每个智能体一个圆形眼睛头像（色块＋眼睛样式） | 配置有 `icon` 字段，但 Builder 不暴露；界面里没有头像 | 需前端 | 用 id 哈希出颜色和眼睛样式，允许在「名称与头像」里改，存进 `icon` |
| A13 | 发布阶段「申请上架市场」 | 只有管理员在 /admin/market 直接上下架，没有申请流程 | 需后端 | 新增申请记录和管理端审核队列；或者只放一句「联系管理员上架」 |
| A14 | 新建弹层的「从模板」 | 没有模板库；只有从市场克隆 | 需后端 | 先只保留「从市场克隆」，模板库以后做 |
| A15 | 分享给「财务部（组）」这类组授权 | API 支持组，但产品有意去掉了组（「一个账号即一家企业」） | 产品决定 | 定向分享只做「按账号」，组授权只展示遗留记录、可撤销 |
| A16 | 接入阶段「在线试调」：填入参、运行、看返回 JSON | invoke / result API 已有，只出现在代码示例里 | 需前端 | 用当前用户会话直接调 invoke，返回 runId 和结果 |
| A17 | 运行阶段顶部「7 天调用、失败率、消耗」小统计 | 用量页有按智能体的次数和失败数；没有单个智能体的汇总接口 | 需改造 | 复用 usage 接口加 agent 过滤 |

## B. 现有产品有、dir-2 初稿没画到的（全量原型会补齐，不需要你决定）

推理强度以外的模型字段（最大轮次、别名、已停用模型）、技能包附属文件与路径校验、MCP stdio 与 env、子代理模型、知识检索测试与注入文本、变量与密钥细节、权限模式六种说明、无人值守审批、需审批命令模式、Schema 实时校验、评测用例全部断言字段与运行目标选择、历史评测与配置哈希、版本对比 / 载入草稿 / 设为发布版、删除智能体、Key 限额行内编辑 / 月度上限 / 轮换 / 吊销、Webhook 签名密钥（账号级）与投递记录重发、运行详情、对话里的思考块 / steer / 重跑 / 排队 / 斜杠命令 / 变量条 / 审批条全部状态、工作区文件预览、积分流水与运行消耗下钻、充值订单、用量分析、模型价格、操作日志、登录三种模式，以及管理端全部 6 组页面。

## C. 原型顺带补上的「API 有、UI 无」（需前端，建议直接做）

取消运行、恢复归档会话、查看版本快照、OpenAPI 文档渲染、定向分享给账号（读/写）、推理强度 `effort`、头像 `icon`。
