# Open Web Agents 功能布局重设计

2026-10-27。当前阶段: huashu-design 三方向初稿,等待选择后实施生产页面。

## 需求与假设

用户原话: “感觉功能分布布局，有点不合理，有些功能冗余，重复，应该整体梳理下”。
随后要求“完全使用 huashu-design”。本次从六个候选选择三个制作完整可交互原型。
原设计保留不覆盖,本轮目录独立为 `docs/design-demos/ia-v2`。

场景是企业用户长期使用智能体做事,兼顾创建者与管理员。
桌面 1440x900,窄屏 375x812;三版相同内容、尺寸与业务能力。
不是营销页,第一屏直接是有内容的对话。页面正文 14px 起,移动端正文 16px,
标签 12px 起,主要点击目标 44px。字距为 0。

本次原型不调用模型、不写生产数据库。持久化仅用独立 localStorage 命名空间。
示例资料统一标识“交互样例”,不得把演示运行当真实记录。页面不写技术实现说明。

## 三版共同内容

产品名称 Open Web Agents;品牌沿用现有蓝底 OW 字标,不用任何第三方产品 logo。
共同当前任务: “创建一个简单的 REST API”,归属“通用智能体”。
用户消息: “创建一个简单的 REST API，包含健康检查和用户列表接口。”
回复: “接口结构已整理。健康检查和用户列表使用独立路由，用户列表支持分页。”
交付文件: `src/app.ts`, `src/routes/users.ts`, `README.md`。
工具过程样例: Read README.md 成功,Write src/app.ts 成功,Bash pnpm test 失败。
失败输出: “尚未配置测试脚本”;不得显示真实运行耗时或模型调用价格。
提问样例: “用户数据先放在哪里？”选项“内存数据”“数据库”,未选前提交禁用。

智能体列表: 通用智能体(现有名称)、接口开发助手(样例)、文档整理助手(样例)。
详情包含: 配置、能力、知识、安全与契约、评测、发布与分享。表单切区保留修改。
AI 辅助编辑属于智能体详情,不作为全局一级目的地。
保存只保存原型草稿,发布只能显示样例状态,不能声称调用后台成功。

全局运行: 三条样例记录,分别为工作台/接口调用/评测,状态成功/成功/失败。
来源、状态过滤可用;点击记录可看输入、输出或失败说明,不触发重跑真实任务。
API 接入: 签发样例 Key、按选中智能体生成调用片段、Webhook 配置/投递。
Key 示例明确为不可调用的 demo 值;密码不写真实凭证。
用量与费用: 可用 0、冻结 0,没有计费记录;分析/流水/充值与订单/价格可切换,
不编造账户余额或模型价格。充值只演示订单确认,不进行真实支付。
平台管理: 独立区域,账号/模型与算力/计费/运营审计,用样例管理员身份预览。
账号设置: 头像内的账号安全与操作日志,不与 API Key 混合。

## 最小可验证交互

导航可回到工作台;会话切换、新建、发送本地消息;文件/执行详情开关与展开;
提问选择和提交;智能体详情切区并保留草稿,保存反馈;运行过滤和详情;
API 示例切换;用量费用子视图;个人与平台区域区分;搜索面板可搜目的地,
Escape 关闭并恢复焦点;375px 可操作且页面无横向溢出。

## 设计边界

维持 `.dark` 的真实色值: 主区 #1e1f22,面板 #2b2d30,边框 #393b40,
主色 #3574f0,亮蓝 #548af7,选中 #2e436e,正文 #dfe1e5。
次要文本可提高至 #a7abb3 以保证可读性。成功 #5fb865,错误 #db5c5c,
警告 #e0b153 只表达状态。拒绝深蓝大面积底色、渐变、装饰大标题。
圆角: 面板 12px(用户已认可),控件 6px,标签 4px。面板间隔 6px。
字体: 系统无衬线/PingFang SC;代码使用系统等宽。离线可打开。
图标使用项目已安装的 lucide 官方 icon node 输出为内嵌 SVG,不得手绘图标。
HTML 每版一个自包含文件,不依赖 CDN。必要代码注释说明假设。
每版 <=1000 行。交付首屏、完整页面及手机截图,并记录交互验证。

## Form 五问

角色是操作界面;观看距离是笔记本与手机;视觉温度安静、可靠。
容量以一段完整对话、三条工具调用、一份待回答问题和输入框作为基准。
视觉组织来自“智能体配置 -> 会话 -> 运行 -> 文件”关系,
不把通用财务仪表盘或 IDE 的所有工具栏照搬进来。

## 生产范围

正式代码等方向选定后再改。三版中无论选择哪版,必须保留会话/运行区别、
草稿/发布区别、用量/结算区别、权限与密钥边界、旧 URL 和深链接。
