## 修正记录

- 第一轮三个原型的品牌字标文字对比度不足,改为白字。
- 禁用提问按钮以可读的灰色表达禁用,避免通过整体低透明度牺牲文字可读性。
- 选中行的次要文字与失败状态文字提高对比度。
- 去掉重复的样例标识、底部实现说明和重复的新建会话按钮。
- 有 ARIA tab 角色而没有相应键盘行为的控件,改成准确表达状态的原生导航按钮。
- A 调整正文间距,使问题与提交控件更容易出现在首屏可见区。

## 为什么保留部分体检提示

脚本把系统 UI 字体用于标题标为黄色提示。本项目是长时间操作的工具界面,
沿用已经确认的系统字体和紧凑标题,不为了消除提示替换成营销页展示字体。
真实代码、路径、Key 的等宽字体有语义作用,不属于装饰性小标签。
比较入口 index.html 是目录入口而非独立交付原型,其截图采用同目录相对路径;
三个 dir-*.html 才是自包含的离线可操作原型。整目录移动时比较页链接保持有效。

## 初步评审

- A 的任务入口最易发现;代价是桌面会常驻两列导航,需要让当前智能体上下文随跳转保留。
- B 最符合 Agent > Session > Run 的对象关系;代价是跨智能体工作需要全局入口。
- C 对长对话最友好,手机适配自然;代价是历史会话的访问多一次展开。
- 不以自评分数代替用户选择。三个原型都保留明确的权衡,没有预先替用户批准方向。

## 原型能力限制

所有保存、Key、消息、订单均为本地交互样例。AI 辅助只演示草稿修改流程,
不生成真实模型结果;样例签名密钥不可调用,不会付款或扣积分。
生产实现仍需验证服务端授权、计费、发布评测、会话恢复与真实运行流。
