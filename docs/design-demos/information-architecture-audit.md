# 功能布局梳理与调整方案

日期: 2026-10-27

状态: 已完成现状梳理,以下为建议方案,尚未实施导航和页面迁移。

后续状态: 用户经 huashu-design 三方向原型选择 B「对象工作区」。
下文五任务导航是早期建议,不作为最终布局;最终采用智能体对象树及对象内四个页签。
生产实现与验证见 `ia-v2/implementation/README.md`。

## 范围与结论

依据当前工作区源码检查 24 个 page.tsx,其中 3 个是兼容重定向、1 个是登录页,
其余 20 个是功能页面。检查了全局导航、两套命令面板、工作台、构建器、AI 编辑、
市场、接入、运行、审计、用量、积分、套餐、账号与模型管理的页面组成。
浏览器补查了普通账号的智能体编辑页;工作台和账号设置沿用本轮圆角修改时的实际检查。
管理员页面本轮以源码为依据,没有更改账号权限、业务数据或发起模型调用。

问题主要在信息架构:功能按历史开发模块累积,没有按用户当前任务组织。
“换成 IDE 外壳”统一了样式,但同时增加了标签、窗口条和状态栏,部分操作被重复呈现。
保留已经确认的面板圆角与间距,这次调整功能归属、操作层级和信息密度。

## 已确认的问题

| 优先级 | 现状与证据 | 调整建议 |
| --- | --- | --- |
| P1 | `ide/nav.ts` 的 PERSONAL_NAV 将运行、接入、用量、积分、套餐、算力全归入账号设置;“账号设置”默认进入 API Key | 把日常业务移出设置;设置只保留账号安全和个人操作日志 |
| P1 | 工作台会话列表、会话标签、顶部会话名重复表达当前位置;`openSession` 每次重新加载历史,没有为每个标签维护独立输入状态 | 默认保留会话列表和单个会话标题,移除持久化标签管理;未来有明确多会话工作需求再单独设计 |
| P1 | 工作台右侧图标栏和面板内部标签都切换文件/运行;顶部停止和输入框停止都调用 `cancelRun` | 对话标题行提供一个“详情”开关,侧面板内部用“文件 / 执行详情”切换;停止以输入框为主,顶部只显示运行状态 |
| P1 | `builder.tsx` 把基本信息、技能、MCP、子代理、安全、契约、发布、评测、知识、分享、调用代码串成一个长表单 | 智能体详情按任务分区,保持同一份草稿状态,避免切页丢失修改 |
| P1 | 构建器底部和接入中心均有调用示例;前者传入当前表单契约,后者默认用已发布契约,可能展示不同入参 | 正式接入文档以已发布版本为准,未发布时明确标草稿;构建器提供携带 agentId 的接入链接,草稿测试单独标识 |
| P1 | token 用量页、积分账户、套餐页、平台算力分散;运行记录、用量明细、运行消耗又各列一次运行 | 合为“用量与费用”一级区域,保留不同口径的子视图,以 runId 互相定位 |
| P1 | 工作台 CommandPalette 独立维护 PAGES,缺少积分、套餐、AI 编辑及管理页;其他页面 NavPalette 则包含这些入口 | 所有页面共享一份角色可见的导航定义,工作台额外加入会话搜索和上下文操作 |
| P2 | 模型提供者页含默认模型别名;提供者详情维护模型;模型总览跳回详情;“平台算力”实际是公开状态和售价 | 管理端统一归为“模型与算力”,下设模型、提供者、默认路由;用户端公开价格归到用量与费用 |
| P2 | 管理端积分页同时显示对账、全平台汇总、批量发放、待核对、单账号余额、明细和流水,各自刷新 | 按“概览 / 账户 / 对账”分视图,当前视图一个刷新入口,发放积分作为明确操作 |
| P2 | 个人设置树混列平台管理;运行和审计页用“全平台”复选框切范围;市场页还含上下架管理 | 个人和平台区域分开,管理员从平台管理进入全平台视图;范围必须在标题和筛选中明确显示 |
| P2 | 头像菜单重复列账号设置和平台管理;状态栏又重复账号身份 | 头像负责身份、账号设置、退出;平台管理只有全局导航入口,状态栏移除身份重复 |
| P2 | 状态栏“已连接”只基于 navigator.onLine;余额仅挂载时读取 | 网络正常不能表示运行流已连通;只在离线/重连时显示连接提示,余额按运行结算刷新或显示更新时间 |

P1 表示优先修正的任务路径问题,P2 表示随后收敛的布局和表达问题,不代表安全漏洞等级。

## 建议的信息架构

普通账号的主导航按工作任务组织,桌面默认显示图标和短标签,可折叠。
不再用“点击当前导航项”同时承担收起面板的操作,收起由专用控件承担。

| 一级区域 | 内容 | 默认落点 |
| --- | --- | --- |
| 工作台 | 会话列表、对话、文件与执行详情 | 当前会话或新会话 |
| 智能体 | 我的智能体、发现智能体;详情内配置、评测、发布等 | 我的智能体列表 |
| 运行记录 | Web/API/评测/AI 编辑的执行记录、筛选、结果与错误 | 我的运行 |
| API 接入 | API Key、按智能体的调用文档、Webhook 签名与投递记录 | API Key |
| 用量与费用 | 概览、用量分析、账户流水、充值与订单、模型价格 | 余额与消耗概览 |

账号设置从头像进入,包含账号安全与个人操作日志。
平台管理是仅管理员可见的独立入口,分为:

| 管理区域 | 子视图 |
| --- | --- |
| 账号 | 列表、角色、额度、停用、密码 |
| 模型与算力 | 模型、提供者、默认路由 |
| 计费 | 消耗概览、账号余额与流水、对账与待核对 |
| 套餐与订单 | 套餐目录、订单处理 |
| 平台运行 | 全平台运行记录、用量统计 |
| 平台审计 | 全平台操作日志 |
| 市场管理 | 上下架管理 |

管理端是在现有能力上重新归类,不意味着新增后台接口或放宽查看权限。
个人余额、个人统计与全平台统计不能因合并导航而混成一个数据范围。

## 工作台具体布局

1. 主导航负责换任务区域;会话侧栏只负责查找、创建、归档、删除会话。
2. 对话区顶部只显示一个当前会话标题和其智能体,以及详情开关。
3. 新建时选择智能体;已有会话显示其归属,不把“切换智能体并新开会话”伪装成更改当前会话。
4. 默认只有对话区;文件/执行详情按需打开。用户主动打开后记住偏好。
5. 取消右侧独立图标条,保留详情面板内的一组切换控件。
6. 对话中的工具摘要保留,便于理解回答;详情面板负责检查输入输出。点“查看详情”定位到对应工具,
   不要求用户在第二棵树里重新寻找。移动端无法常驻侧面板时,仍能从对话打开详情抽屉。
7. 输入框保留发送、停止、补充消息、附件及上下文用量;审批与提问留在对应运行上下文内。
8. 不同时显示三份会话名,不同时显示两个常驻停止按钮。
9. 余额只保留一个紧凑入口;离线与重连异常可见,正常状态不持续占用注意力。

会话列表与搜索不是冗余:前者用于浏览,后者用于定位。
工具摘要与执行详情也不是冗余:前者解释过程,后者排错。
应减少重复的完整内容和控制器,不是删除这些能力。

## 智能体详情具体分区

| 分区 | 内容 |
| --- | --- |
| 配置 | 名称、描述、开场建议、系统提示、模型、最大轮次 |
| 能力 | 技能、MCP、子代理、工具白名单、变量与密钥 |
| 知识 | 知识文档、上传、检索相关配置 |
| 安全与契约 | 权限模式、审批策略、输入/输出契约 |
| 评测 | 用例、执行、结果与历史 |
| 发布与分享 | 草稿/发布版本、恢复、可见范围、分享权限 |

顶部固定当前智能体、草稿/发布状态、保存、试运行和 AI 辅助编辑。
AI 编辑是当前智能体的一种编辑方式,不再作为独立一级产品入口。
AI 设计历史保留,并明确关联目标智能体;尚未绑定的设计从创建流程进入。
“API 接入”是携带 agentId 的上下文链接,Webhook 地址的编辑仍按所有者权限控制。

切分表单时不能拆坏:未保存提示、发布前评测要求、发布与草稿的契约区别、只读分享、
变量密钥不回显、知识上传状态。切换分区应保留草稿与校验错误。

## 需要保留的数据区别

- 会话是多轮上下文,运行是一次执行;全局运行列表不能被会话列表替代。
- token/SDK 报告成本、按售价估算积分、实际结算积分不是同一个数。
  页面归到一起后仍要明确口径,不能把技术成本当用户账单。
- 运行消耗是执行维度,账户流水是资金变化维度;冻结、释放、退款不能合并掉。
- 个人模型价格只展示公开售价;提供者凭证、内部地址、成本等仍只在管理范围。
- 运行日志与审计日志分别回答“任务发生了什么”和“谁修改了什么”,不合并底层记录。
- 草稿试运行、已发布版本使用、评测运行保持各自语义。
- 命令面板和上下文链接是快捷路径,可以存在;它们应共用导航和权限定义。

## 路由迁移方案

先调整界面归属,保留现有 URL 与查询参数;无需为菜单重组立即搬动所有路由文件。

| 现有地址 | 新归属 |
| --- | --- |
| `/` | 工作台 |
| `/agents`, `/agents/design` | 智能体列表/详情与 AI 辅助编辑 |
| `/market`, `/market/[id]` | 智能体 > 发现 |
| `/settings/runs` | 运行记录 |
| `/settings/keys?agent=...` | API 接入,保留指定智能体上下文 |
| `/settings/usage` | 用量与费用 > 用量分析 |
| `/settings/billing` | 用量与费用 > 概览与流水 |
| `/settings/packages` | 用量与费用 > 充值与订单 |
| `/settings/credentials` | 用量与费用 > 模型价格与公开状态 |
| `/settings/account`, `/settings/audit` | 账号设置 |
| `/admin/*` | 对应平台管理分组,保留角色校验 |

若后续改成新的业务 URL,旧地址必须重定向并保留 session、agent、id、tab、筛选等参数。
当前 `/settings`、`/usage`、`/admin/capabilities` 已是兼容重定向,不应被统计成重复功能页。

## 实施顺序与验收

1. 统一导航定义与命令面板,建立新分组;个人/平台范围可见,不改变服务端授权。
2. 精简工作台:会话标题、右侧面板入口、停止操作,保留圆角与缩放能力。
3. 切分智能体详情:同一草稿状态跨分区保留,正式接入示例集中,AI 编辑可回到目标智能体。
4. 归并用量与费用,拆开管理端大页面,统一筛选与刷新范围。
5. 清理文案和失效指引。例如构建器仍提示在“模型凭证”页设置签名密钥,
   实际入口已在接入中心;outputSchema 文案又写“填了才能被系统当接口调用”,
   与当前支持文本调用的界面说明不一致。

完成标准:

- 普通用户能从主导航直接找到“聊天、建智能体、查运行、接 API、看费用”。
- 同一操作只有一个主入口,快捷搜索与上下文链接使用相同语义。
- 新用户进入智能体页先看到列表与创建入口,而不是默认进入整页新建表单。
- 同一智能体的配置、评测、发布和接入跳转始终携带正确 id 与版本语义。
- 默认工作台不为无内容的右侧窗口预留空间。
- 个人与全平台页面不依赖隐蔽复选框解释数据范围。
- 桌面和 375px 窄屏可完成选择会话、提问、审批、停止、查看文件与工具详情。
- 回归现有会话恢复、分支重跑、发布评测、Key 权限、账单、账号管理测试。
- 逐个检查旧链接与深链接;除界面组织外,不改运行内核、计费口径与资源权限。
